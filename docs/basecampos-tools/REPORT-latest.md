## 10:40 ROOT CAUSE of runs 1-3 FOUND: `noatime` in rootflags
The diag initramfs (label initramfs-diag; log /var/log/initramfs-diag.log, kept in ~/duet/reports/basecampos/initramfs-diag.log) shows the CI kernel mounts /dev/mmcblk0p1 fine with ro, subvol=@debtest, subvol=@basecampos and rw,subvol=@basecampos,noatime (rc=0, partitions are ready at 0.90 s, before /init at 0.91 s) - but via busybox `mount -o`, which turns noatime into the VFS flag MS_NOATIME. On the kernel command line `rootflags=` is passed RAW as the filesystem data string, and btrfs does not know `noatime` as a data option -> mount fails (EINVAL) -> panic -> panic=10 reboot -> firmware falls back to KERN-B. All my run 1-3 cmdlines (and the @debtest one) contained `noatime` (run 1 additionally LABEL=). Fix: rootflags=subvol=@basecampos only (atime stays default; NixOS' fstab remounts / with noatime later). Run 4 = same BasecampOS blob + init=/diag-init without noatime.
